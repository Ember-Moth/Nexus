# 产品范围

Nexus 为企业客户提供统一的 AI API 调用入口与可核对的费用记录。首期工作集中在控制平面，完成企业开户、发放调用凭据、配置上游、充值入账、计量结算和费用查询的业务流程。

## 已确认的产品决定

| 决定 | 内容 |
| --- | --- |
| 客户类型 | 使用 API 的企业客户，组织是客户和结算主体 |
| 系统拆分 | 控制平面与数据平面分离 |
| 当前技术栈 | Python、FastAPI、uvloop、PostgreSQL |
| 后续网关 | Rust，无状态，可横向扩容，部署在负载均衡后 |
| 平面通信 | 使用 PostgreSQL、Redis 协作，具体协议见通信文档 |
| 首期结算 | 预付费余额扣费，人工入账与支付确认后的自动入账共用账本 |
| 支付接入 | 先定义通用接口，具体支付网关稍后确定 |
| 差异化定价 | 独立的上游成本表、统一售价表、客户折扣规则 |
| 计量和时效 | 输入、缓存、补全等按 Token 计费，自动化、接近实时扣费 |
| 当前产出 | v1.0 设计已定稿；后续实现控制平面，不提前开发 Rust 网关 |

## 使用者和边界

平台运营人员管理客户、模型和上游；平台财务人员登记到账、处理账务调整；企业管理员管理本组织的成员、项目和调用凭据；企业开发者管理获授权的项目并查看其用量；企业财务查看本组织的费用和流水。

成员代表人，服务账号代表客户的应用。首期调用 Key 统一归属于项目内的服务账号，避免员工离职影响应用身份。一个服务账号可以有多个 Key，以支持平滑轮换。

组织拥有独立的计费账户；项目用于权限和成本归属。首期不实现企业部门树、组织间转账、经销商层级或多级分销。

## 首期交付

| 领域 | 控制平面交付 | 验收结果 |
| --- | --- | --- |
| 身份 | 用户、组织、成员、固定角色、项目、服务账号 | 越权访问被拒绝，跨组织资源无法关联 |
| 凭据 | Key 创建、查看标识、撤销、轮换、模型权限 | 明文只在创建时返回，撤销后无法获得新的调用授权 |
| 上游 | 上游地址、加密凭据、模型目录、部署映射 | 能校验配置并生成可供网关使用的快照 |
| 策略 | 模型白名单、优先级和权重、限速、并发、金额预算 | 发布有版本，策略能由模拟器消费 |
| 定价 | 统一售价、客户折扣、上游成本价 | 历史调用使用当时锁定的售价、折扣和成本版本 |
| 账户 | 人工入账、支付确认入账、预留、扣费、释放、调整 | 每笔资金变化有来源，同一收款不能重复入账 |
| 支付 | 通用适配器、充值订单、通知收件箱、查单补偿、支付对账 | 模拟适配器验证自动入账，真实渠道另行接入验收 |
| 计量 | Token 用量接收、验证、归一化、自动结算、异常队列 | 正常请求自动近实时扣费，重试不重扣，缺失用量不视为零 |
| 查询 | 请求元数据、用量、费用、余额、流水、导出 | 按组织、项目、Key、模型和时间筛选 |
| 审计 | 权限、凭据、配置、入账和调整操作 | 能追溯操作人、时间、对象和原因 |

首期管理能力以 API 和自动生成的接口说明交付。支付接口返回托管收银台地址或支付码，自建管理网站、企业门户和收银页面不在本阶段范围内。

金额预算与资金余额分别管理：余额表示资金，预算限制一定周期内的消费，RPM、TPM 和并发限制调用速率与容量。预算未耗尽不代表账户有足够资金。

“客户折扣”首期归属于企业组织，同一组织的成员和服务账号共享折扣。使用统一售价乘以折扣系数形成差异化价格，不给每个成员复制一张售价表。首期组织折扣统一作用于支持的 Token 计费项，按模型或计费项覆盖的折扣留作扩展。

人工操作用于登记线下收款和处理异常；通过支付网关核实的收款自动入账，正常调用计量、费用计算、余额扣减与预留释放也自动完成。

## 角色模型

采用固定角色和项目授权，不实现自定义权限编辑器。项目授权只缩小成员权限，不能扩大组织角色的权限。

| 角色 | 作用域 | 主要权限 |
| --- | --- | --- |
| `platform_admin` | 平台 | 用户、组织、平台角色、上游、模型和配置管理 |
| `platform_finance` | 平台 | 人工入账、账务调整、对账与财务导出 |
| `org_owner` | 组织 | 组织成员、项目、服务账号、Key、预算、充值订单和账务查看 |
| `org_developer` | 授权项目 | 服务账号和 Key 管理、模型使用、用量查看 |
| `org_finance` | 组织 | 创建充值订单；查询余额、流水、费用和导出，无直接账本写权限 |

平台管理员不会隐式获得财务写权限；需要执行人工入账时显式授予财务角色。组织内至少保留一位有效 owner。企业成员可以按权限发起支付，但不能直接增加余额、标记已收款、修改销售价或查看上游成本和凭据。

## 首期业务场景

1. 平台创建企业组织、计费账户和企业管理员，企业建立项目及服务账号。
2. 平台配置可销售模型、可用上游和价格，发布配置。
3. 财务登记已到账的线下收款；或企业发起充值，经支付网关服务端确认后由系统自动入账。
4. 企业创建 Key 并分配模型权限、限额，查看余额与可用金额。
5. 协议模拟器以网关身份预留资金，报告上游尝试和实际用量。
6. Worker 结算消费，企业查询费用，平台核对成本、流水和异常记录。

人工登记入账只反映外部已发生的收款。在线支付由具体网关收款，控制平面核实后入账；自动入账不包含余额不足时自动扣卡。消费明细、资金流水和期间汇总不等同于税务发票。

## 后续扩展

以下能力按实际客户需求安排，不进入首期实现：月结与信用额度、自动续费扣款、自动对外退款、SSO、自定义角色、部门报表、专属容量、地域或延迟优化路由、服务等级赔付、自动对接厂商账单。

数据平面的真实转发、流式处理、协议适配、故障切换、压力测试、负载均衡接入和滚动发布属于后续独立阶段。

本项目不包含 Coding Plan 套餐接入、消费者账号池、伪装、防风控、聊天产品、Agent 编排、RAG 知识库、签到或推广返佣。

## 实施时确定的参数

| 参数 | 首期设计处理 | 决定时点 |
| --- | --- | --- |
| 运营币种 | 每个部署首期只启用一种币种；所有金额仍携带币种，不做隐式换汇 | 首次配置账户前 |
| 第一批模型 | 先支持能够可靠归一化 Token 用量并计算预留上限的模型；具体清单待定 | 真实网关接入前 |
| 售价和客户折扣数值 | 数据结构支持版本化售价与折扣，不预设真实报价 | 商业试运行前 |
| 入账是否双人复核 | 首期采用具名财务操作、依据记录和审计；双人复核作为扩展 | 财务试运行前 |
| 支付渠道与支付方式 | 先实现通用契约及模拟适配器；真实渠道须验证确认条件、金额精度和通知协议 | 启用真实自动入账前 |
| 保留期与备份目标 | 按数据类别配置；未确定保留期前不自动删除账务历史 | 生产部署前 |
| 性能和可用性目标 | 用节点数、组织分布、请求率和事件大小建立测试画像，不虚构 SLA | 性能验收前 |

这些是实施或上线配置项，不影响 v1.0 设计定稿，也不阻塞控制平面基础模块开发；按各自决定时点补齐。
